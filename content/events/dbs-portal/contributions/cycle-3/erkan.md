A single real post sets the tone for the start page: what belongs in a scan list, what opens for detail, and how the page reads for colleagues who need the picture fast. It keeps the start page one place, but makes the post treatment stronger so the right things stand out first.

- One real post leads the page and sets the visual tone for the rest of the start page.
- The page shows which content belongs in a list at a glance and which content should open into detail.
- A post reads like an outcome, not activity, so it says what changed and what it meant.
- The list items keep their support details close by, including owner, frequency and BU, so scanning stays fast.
- The layout stays a real internal website with cards, air and clear hierarchy rather than drifting into a wiki.

## What this hand-in decides
- Refine the start page around one strong post-idea that can lead the page.
- Make the difference between list content and opened detail obvious in the layout.
- Keep the page as an internal website front door, not a wiki.

## Content structure
- Use one real post as the tone-setter for the page.
- That post should read as a specific result or change, not a description of work.
- Keep the post copy in the style already agreed: say what changed and what it meant.
- Show clearly which items stay as scan-first list cards and which items open for more detail.
- Keep owner, frequency, track and BU visible where they help scanning.
- Preserve the existing requirement that owner means a person.
- Preserve the need for real content only; no placeholder text.

## Look and feel
- White, airy, left-aligned, navy headings.
- One card per area, with clear hierarchy.
- Keep the start page feeling like the official site rather than a document.
- Make the post that leads the page feel more prominent than the surrounding scan list.
- Keep buttons as round pills and states as small round tags.

## Out of scope
- No new wiki structure.
- No new dashboard or editor flow.
- No extra unrelated page sections.
- No change to the canon’s existing areas beyond this refinement.

## Notes
- Nothing was decided about a new data model for opened detail, so keep the implementation sensible and light.
- The safest reading is that the page should make the list-vs-detail choice easier, not introduce a separate feature area.
- Keep the established DBS front-door structure; this is a refinement of the start page tone and hierarchy.
