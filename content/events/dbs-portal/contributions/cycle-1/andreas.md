A release area for people who need to see what shipped, what is coming next, and what each release meant. It shows the numbers behind rollout progress and the user goal each release moved.

- Shows the number of releases and deployments, not just a timeline
- Explains what changed in each release in plain English
- Makes the user goal met by each release visible
- Separates latest, ongoing, and coming releases
- Keeps the focus on what the releases proved, not on activity

## What this area must do
- Show a simple release view with three states: latest, ongoing, coming.
- Include the release/deploy count as the first thing people read.
- Attach a plain-English outcome to each item: what changed and what it meant.
- Make the user goal explicit: which goal was met, and how we know.

## Content
- Real release numbers only if known; do not invent counts.
- Write the user goal in everyday language, not product jargon.
- If a release has no outcome yet, say that clearly.

## Look and feel
- Match the sprint direction: white page, lots of air, navy headings, left-aligned text.
- Keep it as a web page with one card per area.
- Buttons should be fully round pills: orange primary, navy outline secondary.
- Use small round tags for states.

## Out of scope
- No internal acronyms in headlines.
- No activity-only copy such as "we did X" without the result.
- No placeholder text.
- No extra analysis or backlog detail beyond the releases and their meaning.
