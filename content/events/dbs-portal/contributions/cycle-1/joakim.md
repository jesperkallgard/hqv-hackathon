Land on the local region first, then switch region, view details, or change range to compare what changed since the last visit. It is for a colleague who wants the latest numbers and critical items at a glance.

- Opens on the local region by default and lets the user rearrange the tabs.
- Shows four outsider-named cards: revenue, visitors, notifications, and incidents.
- The first action is to switch region, view details, or change range from the overview.
- Each card shows what changed since the last visit and any critical messages.
- It is a real web page with a header, one wide content column, a footer, and pill buttons.

- Prototype as a real internal web page, not a wiki or document.
- Layout: header with the site name and short navigation, one generous content column, footer, full-width feel.
- Visual style: white background, lots of air, navy headings, left-aligned text.
- Buttons: fully round pills; primary action orange with white text, secondary actions outlined in navy.
- States must be shown as small round tags, not coloured words.
- Default landing state is the local region.
- The overview must support rearranging the tabs/cards.
- The first screen should let the user switch region, view details, and change range.
- The four areas are: revenue, visitors, notifications, and incidents.
- Copy must be written for a colleague outside the team; no internal acronyms in headings.
- Show changes since the last visit, any critical items, any messages, and AI summary insights of the changes.
- Keep it to the smallest useful version: one page, no deep flow.
- Use real content only; placeholder text is not allowed.
- Frequency is part of the content if any feed or post is shown; state whether it is static, monthly, or weekly.
- If a label or phrasing already exists in the product, reuse it instead of inventing a variant.
- Name the track and BU if they are part of the content; keep them in one word each.
